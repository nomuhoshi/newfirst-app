# U3 与写代码 / 改代码题：实现方案（草案）

> 日期：2026-11-03（日本时间）。状态：方案，待 GPT 审查、项目主人确认后再实现。课程大纲见 `docs/curriculum.md`。
> 原则沿用 AGENTS.md：不改 XP、红心、难度、解锁规则；不用预设输出冒充 Python 运行；离线 / 运行不可用时如实提示；新题用真实 Python 验证。

## 1. 范围
- U3「比较与判断」8 关（大纲 U3L1–U3L8）：L1–L4 只用现有 predict / fill / order；L5–L7 每关 1 道 modify；L8 项目 1 道 write。
- 新增两种题型：`modify`（改代码）、`write`（写代码），运行在现有 Pyodide 工作线程（`src/runner.js`、`src/py-worker.js`）。
- 补 U1L7、U2L6 两个 modify 项目关（可与 U3 分开发 PR）。
- 不做：input()、多文件、文件读写（大纲中 ⛔ 关卡）；代码风格评分；AI 判题。

## 2. 题目数据格式
沿用 `content/unit*.json` 的 `exercises` 数组，新增字段，旧题型不变。每道题加稳定 `id`（随机练习 §0.3 已要求）。

```json
{
  "id": "U3L8-W1",
  "type": "write",
  "prompt": "满 100 减 20，会员再减 5。输出：应付 <金额>",
  "given": ["total", "is_vip"],
  "starter": "# total 和 is_vip 已经准备好了\n",
  "tests": [
    { "name": "普通顾客满 100", "vars": { "total": 120, "is_vip": false }, "expected": "应付 100" },
    { "name": "会员满 100",     "vars": { "total": 120, "is_vip": true },  "expected": "应付 95" },
    { "name": "会员不满 100",   "vars": { "total": 80,  "is_vip": true },  "expected": "应付 75" },
    { "name": "刚好 100",       "vars": { "total": 100, "is_vip": false }, "expected": "应付 80", "hidden": false }
  ],
  "reference": "if total >= 100:\n    total = total - 20\nif is_vip:\n    total = total - 5\nprint(\"应付\", total)",
  "alternatives": ["t = total\nif t >= 100:\n    t -= 20\nif is_vip:\n    t -= 5\nprint(f\"应付 {t}\")"],
  "mistakes": [
    { "match": { "test": "刚好 100", "got": "应付 100" }, "why": "满 100 包括 100 本身，要用 >=，不是 >。" }
  ],
  "hints": ["知识点：if 可以连着写两个，互不影响。", "思路：先处理满减，再单独判断会员。"],
  "checkMode": "stdout"
}
```
- `modify` 多一个 `code`（初始程序，能运行但结果错或报错），其余同 `write`。
- `checkMode`：`stdout`（比较输出，默认）或 `call`（U7 起调用函数，`tests[].call` 如 `"price(3)"`，`expected` 为 `repr` 文本）。U3 只用 `stdout`。
- `vars` 只允许 JSON 能表示的值（数字、字符串、布尔、列表、对象），由判题器转成 Python 字面量。
- `mistakes`：按“哪组测试、得到什么输出 / 什么错误类型”匹配的针对性解释；匹配不到时显示通用解释 + 实际输出与期望的差异。
- `hints` 两级；第三级“参考解法”取 `reference`，打开后按 SPEC §4.2 标“已查看解答”。

**内容自动验证（加进 npm test）**：对每道 write / modify：`reference` 和所有 `alternatives` 必须通过全部测试；`modify.code` 原样必须**不通过**至少一组；`tests` ≥ 2 组且 `expected` 互不相同（防止写死输出也能过）；每条 `mistakes` 必须真的能被某个错误程序触发（题目文件里附 `mistakeSamples`）。

## 3. 判题
1. **按测试数据判输出，不比对代码**：任何写法只要每组输出一致都算对 → 自然接受多种合理解。
2. **每组测试单独运行**：每次在新的全局作用域里先赋值 `vars`，再执行学生代码（SPEC §8.2“每次执行采用新作用域”）。worker 里用 `exec(code, fresh_globals)`；不复用上一组的变量。
3. **至少两组**，且至少一组公开、显示在题面；项目 / 毕业作品可以再加 `hidden` 测试，失败时只显示“还有一组隐藏测试没通过”和测试名，不显示期望值。
4. **比较规则**（SPEC §4.2）：只统一换行符和末尾一个换行；行内空格、标点、大小写都要一致。数字题尽量整数；需要小数的题题干写明显示精度。
5. **防写死**：两组 `expected` 不同；若学生代码里出现所有期望输出的字面量且不引用任何 `given` 变量，给提示“看起来是直接写了答案，换一组数据就不对了”，仍判错（只对 write/modify 的 stdout 题生效，阈值写进测试）。
6. **超时**：沿用 runner 单次 5 秒（不含加载）；多组测试共享一次 Run 时每组各 5 秒、总上限 10 秒；超时显示“运行超过 5 秒，可能是死循环（while 条件一直成立？）”，终止并重启 worker，**编辑器内容保留**。输出上限沿用 100 行 / 8 KiB。
7. **Python 不可用时绝不假装通过**：加载中、加载失败、离线未缓存 Pyodide、worker 创建失败或无响应 → “检查”按钮变为“Python 还没准备好”，不可提交、不计对错、不扣红心；提供“重试加载”；点选题（P/F/O）照常可做。判题结果只来自本次真实运行。
8. **结果展示**：逐组列出 ✓/✗、测试名、期望 vs 实际（差异处高亮 + 文字说明，不只靠颜色）、错误类型与行号的中文解释（复用 `src/errors.js`）。“运行成功”和“通过”分开显示。
9. **草稿保存**：每道 write/modify 的代码按题目 `id` 存 localStorage（键 `suipian.draft.<id>`，独立于 v3 进度，不改进度格式）；输入后 500 ms 防抖保存；运行、看提示、切后台、超时重启都不清空；“重新开始”按钮二次确认后恢复 `starter`/`code`。通过后保留最后一版代码供查看。草稿不进云同步（如要同步需另定）。

## 4. 手机编辑器（iPhone 键盘）
- 复用 lab.html 已验证的 CodeMirror 编辑器 + 内置编程键盘（`src/editor.js`、`src/keyboard.js`），按 SPEC §4.1 规则：Tab=4 空格、Enter 续缩进、冒号后自动加一级、括号引号配对、Undo ≥20 步。
- 默认内置键盘（避免 iOS 自动大写、智能引号 “” 、自动更正把 `if` 改成 `If`）；保留“系统键盘”切换，系统键盘时设置 `autocapitalize=off autocorrect=off spellcheck=false`，并在判题前把弯引号替换检测出来提示（不静默替换）。
- 布局（竖屏）：题目可折叠 → 编辑器（当前行始终可见）→ 测试结果 → 底部操作栏 `Run` `Check` `Hint`；键盘打开时操作栏贴在键盘上方。横屏 / iPad：左题右码。
- 快捷词块栏：本题常用词（`if` `else` `>=` `==` `print` 变量名），不直接给出整句答案。
- 无障碍：编辑器 aria-label、测试结果 aria-live、错误文字不只靠颜色；弹窗沿用 PR #14 的焦点管理。

## 5. 与现有 XP / 红心规则的衔接（不改规则）
| 场景 | 按现有规则的处理 | 是否需要项目主人批准 |
|---|---|---|
| write/modify 首次“检查”通过 | 视为“答对一题” +10 XP（同现有题） | 否（沿用） |
| “检查”未通过 | 现有规则：答错扣 1 红心、本题放到本关最后 | **是**：写代码题一次没过就扣心对新手偏重。备选：①照旧；②只有“检查”扣心，“运行”不扣（推荐，运行=试一试）；③第一次检查不扣。②不改规则本身，只定义“运行不算作答” |
| 点“运行”（不判题） | 不计分、不扣心 | 需确认“运行不算作答”这个定义 |
| 看了参考解法后通过 | SPEC §4.2：标“已查看解答”，需另做一道变化练习 | **是**：现有关卡模式里没有“变化练习”，需决定用“同题换一组数据再写一次”还是不加 XP |
| Python 不可用 | 不能提交 → 不扣心不加分 | 否 |
| 超时 / 运行错误后检查 | 按“未通过”处理 | 随第 2 行决定 |
| 复习关里的 write/modify | 复习规则：不扣心，每题 +5 XP | 否 |
| 随机练习 | 无奖励（§0.3） | 否 |
| 0 红心 | 不能开始新关（含项目关） | 否 |
| 草稿 | 不影响任何计分 | 否 |

## 6. 测试计划
- **内容验证**（node + 真实 Python，CI）：§2 的五条；U3 新 P/F/O 题沿用现有三条（选项与真实输出一致、填空错误词块有解释、排序全排列）。
- **判题单元测试**：多种正确写法都通过；写死输出被拒；作用域隔离（第一组定义的变量在第二组不存在）；换行 / 末尾空格规则；隐藏测试不泄露期望值；`mistakes` 匹配。
- **运行异常**：死循环 → 超时提示且编辑器内容保留、worker 重启后可再运行；输出洪水 → 上限提示；worker 创建失败 / 无响应 / Pyodide 404 / 离线 → 显示“Python 还没准备好”、不可提交、不扣心、XP/红心不变。
- **草稿**：输入→刷新→恢复；切后台→返回；超时重启后仍在；“重新开始”确认后才清空；不同题互不覆盖。
- **计分**：连点“检查”只算一次；通过 +10 一次；未通过按 §5 选定方案；复习关 +5 不扣心；随机练习无变化；主线 v3 数据格式不变。
- **编辑器（Playwright WebKit iPhone / iPad 模拟 + 真机清单）**：内置键盘输入 `if total >= 100:` 回车自动缩进；Tab / 退缩进；系统键盘下弯引号提示；键盘打开时当前行和“检查”可见可点（真机验证，模拟不能代替）。
- **人工试玩**：项目主人 iPhone 上完成 U3L5–L8，记录到 docs/07 清单。

## 8. 风险
- 手机上写代码很慢：U3 写代码题控制在 3–6 行；modify 优先于 write。
- 内置键盘在 iOS 上抑制系统键盘的可靠性需真机确认（SPEC §4.1 已列）。
- 首次加载 Pyodide 约 12 MB：U3 前几关是点选题，可在此期间后台加载。
- 大陆网络：Pyodide 文件拨测可达（cn-recheck 报告），但真机加载未验证。
