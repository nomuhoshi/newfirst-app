## 2. 原则

AI 时代的程序员要三件事：看得懂代码（含 AI 写的）、判断得出对不对、把需求拆清楚。前两件适合手机点选；“自己写”要等代码题运行器。所以：

- 题量按学习目标定，不按固定数字凑。简单概念讲清就过；综合关再把前面的串起来练。
- “能看懂”和“能自己写”分开验收：先用点选题验收看懂；后续给函数和小项目补**短代码题**，再单独验收能自己写。
- 先复用现有点选题型（选输出、填空、排序、读报错选择题）；新交互（如“标出问题行”）等样板验收后再决定是否开发。

## 3. 排期

**A. 基础线（U6 → U7 → U8 → U9）**
1. U6：用 #51，逐关验收后进候选。
2. U7：用 #48，逐关验收。
3. U8：内容分支已存，U6、U7 之后接上。
4. U9 小项目：先定学习目标和题纲，再写题。

**B. 下一条课程线：读代码与调试 → 测试思维 → 审查 AI 代码**
- 第一步只做**一个手机端样板关**，用同一段短代码串起三个动作：
  1. 追踪变量（这段代码跑完，变量是多少）；
  2. 挑出能暴露错误的测试输入（哪组输入会让它出错）；
  3. 选出满足需求的修复（几个修复版本里哪个对）。
- 样板只用现有点选题型。样板验收（手机上读得清、答得顺、答案唯一）之后，才决定是否开发“标出问题行”等新交互，再整条线展开。
- 样板关的代码、需求描述、干扰项设计属于课程设计判断，**需要 Opus**；写题和机械校对可以交给 Sonnet。

**C. 保留在路线图，暂不排期**
Python 进阶（异常、推导式、import、类入门、文件、JSON / CSV）、数据库与 SQL、数据处理（pandas）、算法基础、和外部世界连接（HTTP / API / 调用 AI 接口）、工程习惯（命令行、git、项目结构）。其中依赖代码题运行器或 Pyodide 附加包（pandas、sqlite3）的，要按需加载，不能拖慢首屏（现在 Lighthouse 99）。

## 4. 边界

- 手机点选训练“读”和“判断”，训练不了“写”；发布说明不写“可在课程中输入并运行自己的代码”。
- API、工程习惯在手机上只能讲概念和用模拟数据，不发真实请求。
- 本文是程序员视角的建议，课程内容、章节和排期以产品官的决定为准。
