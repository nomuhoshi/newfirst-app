## 2. 原则

AI 时代的程序员要三件事：看得懂代码（含 AI 写的）、判断得出对不对、把需求拆清楚。前两件适合手机点选；“自己写”要等代码题运行器。所以：

- 题量按学习目标定，不按固定数字凑。简单概念讲清就过；综合关再把前面的串起来练。
- “能看懂”和“能自己写”分开验收：先用点选题验收看懂；后续给函数和小项目补**短代码题**，再单独验收能自己写。
- 先复用现有点选题型（选输出、填空、排序、读报错选择题）；新交互（如“标出问题行”）等样板验收后再决定是否开发。

## 3. 排期

**A. 基础线（U6 → U7 → U8 → U9）**
1. U6：用 #51，逐关验收后进候选。
2. U7：用 #48，逐关验收。
3. U8：内容分支已存，U6、U7 之后接上。
4. U9 小项目：先定学习目标和题纲，再写题。

**B. 下一条课程线：读代码与调试 → 测试思维 → 审查 AI 代码**
- 第一步只做**一个手机端样板关**，用同一段短代码串起三个动作：
  1. 追踪变量（这段代码跑完，变量是多少）；
  2. 挑出能暴露错误的测试输入（哪组输入会让它出错）；
  3. 选出满足需求的修复（几个修复版本里哪个对）。
- 样板只用现有点选题型。样板验收（手机上读得清、答得顺、答案唯一）之后，才决定是否开发“标出问题行”等新交互，再整条线展开。
- 样板关的代码、需求描述、干扰项设计属于课程设计判断，**需要 Opus**；写题和机械校对可以交给 Sonnet。

**C. 保留在路线图，暂不排期**
Python 进阶（异常、推导式、import、类入门、文件、JSON / CSV）、数据库与 SQL、数据处理（pandas）、算法基础、和外部世界连接（HTTP / API / 调用 AI 接口）、工程习惯（命令行、git、项目结构）。其中依赖代码题运行器或 Pyodide 附加包（pandas、sqlite3）的，要按需加载，不能拖慢首屏（现在 Lighthouse 99）。

## 4. 边界

- 手机点选训练“读”和“判断”，训练不了“写”；发布说明不写“可在课程中输入并运行自己的代码”。
- API、工程习惯在手机上只能讲概念和用模拟数据，不发真实请求。
- 本文是程序员视角的建议，课程内容、章节和排期以产品官的决定为准。

### 5.2 通读和校验结果

- 校验：默认的 `verify-content.py` **不包含 unit8**（草稿单元要加 `--extra content/unit8.json`）。加上之后，原 U8 在真实 Python 下失败 0 项（选输出 495、填空 373、排序 94029、读报错 173、代码题 pending 398）。这一条替换我此前回报里“已跑过 U8 校验”的说法：那次没有带 `--extra`，实际没有覆盖 U8。
- 通读 6 关 24 题 + L7 点选题：题面、答案、每个错选项的错因没有发现事实错误；错因都指出了对应的真实现象（NameError / TypeError / SyntaxError 分别对应什么）。作用域的说法已经收窄，不会教出“函数里永远看不到外面”。
- 每题正确选项在源文件里都排第 1 位，靠应用运行时打乱（`shuffleExercise`），不是内容问题，但**浏览器里要看一眼 U8 的选输出题确实被打乱**。

### 5.3 发现的问题（按重要程度）

1. **依赖 pick（读报错选择题）**：U8 可玩的 24 题里有 6 道 pick（连 L7 共 7 道）。U6 的 pick 还没有真机验收；如果真机上有问题，U8 这些题要一起改。U8 应排在 pick 真机验收之后再接。
2. **讲解篇幅超过现在的设计规则**：U8 每关讲解 180–313 字（L3 最长 313），U5 是 85–145 字，U7 的测试要求不超过 140 字。U8 写在这条规则之前，需要产品官决定：缩短到 140 字内，还是函数这种概念密度高的单元允许例外。
3. **开场示例有 7 行超过 22 格宽**（手机代码块上限，全角算 2）：如 `def total(price, cups=1):`（25）、`    print("来一杯", drink)`（26）、`def late_fee(days, rate=2):`（27）。需要在 390 宽手机上实际看有没有换行或横滚；这是预览要验的，不是内容错。
4. **读报错选项里有较长的整句**（最长 57 格，如 L6 Q4“在函数里加一行 return result，最后一行改成 print(calc(8))”）。U6 的 pick 同样是句子，按 #52 的验收口径看窄屏换行是否读得全；U8 用同一口径验。
5. **代码行宽的 28 格规则**：U8 的题目代码没有超过 28 格的行（已查）。

### 5.4 已覆盖的知识点和缺口

已覆盖：定义与调用、先定义后调用、参数与传值、漏传报错、return 与 print、None、return 后不再运行、组合与嵌套调用、多参数与默认值、默认参数的位置规则、局部名字不能在函数外用、函数里赋值不影响外面。

缺口（建议优先级）：

| 优先级 | 知识点 | 说明 |
|---|---|---|
| 高 | 忘写括号：`welcome` 不等于 `welcome()` | 新手最常见的错，现在没有任何题碰到 |
| 高 | 传多了值：TypeError “takes 1 positional argument but 2 were given” | 现在只有“传少了” |
| 高 | 函数里用 if，多处 return | L7 的点选题碰到了，但 L7 暂缓，6 关里没有 |
| 中 | 关键字传参 `total(price=8, cups=3)` 和顺序错乱 | 能读懂别人（含 AI）写的调用 |
| 中 | 函数和列表、循环配合（把列表传进去、在循环里调用） | 与 U5 列表衔接；先点选题读代码即可 |
| 低 | 命名、注释、什么时候该把重复代码抽成函数 | 偏判断力，可放进 U9 小项目 |
| 不排 | 返回多个值、global、可变参数、默认值是列表的陷阱 | 超出第一阶段，先不教 |
