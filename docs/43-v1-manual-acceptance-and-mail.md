> 登录系统其他验收（真实双会话同步、Safari / PWA 登录、DB-3 等）继续，不依赖此项；发信配置完成前，QQ / 163 项仍记「环境阻塞」。


前提（10:30 已定）：域名 `suipiancode.com`（Cloudflare 注册，DNS 在 Cloudflare 的说法待确认访问方式，见上方待办）。没有这个前提时才需要报备选域名和价格。

1. 发信子域名：`mail.suipiancode.com`（避免影响主域名收发信）。
2. Resend 后台添加域名，取得要添加的记录；在 DNS 管理处添加，等状态变为 Verified：
   - DKIM（Resend 给的 TXT 或 CNAME）
   - SPF（TXT，`include:` Resend 指定的值；回执用的 MX/TXT 一并加）
   - DMARC：`_dmarc.<域名>` TXT，先 `v=DMARC1; p=none; rua=mailto:<可收信的邮箱>`
3. Resend 创建 API key，权限只给发信；**不进仓库、不贴聊天、不写日志**。
4. Supabase 正式项目 Authentication → SMTP Settings（需授权后写入）：Host `smtp.resend.com`，端口 465（SSL）或 587，用户名 `resend`，密码 = 上一步的 key，发件人 = 已验证域名下的地址，名称“碎片编程”。
5. 邮件模板中文化；核对发信频率上限（Supabase 内置发信上限很低，上线前按预期用量调整），并确认验证码有效期与应用文案一致。
6. 先在**测试项目**上配同样的 SMTP 走一遍，再动正式项目；正式项目的改动只在老大授权后做，且先做只读核查（docs/40 §4）。

## 3. Gmail / QQ / 163 实测步骤

每个邮箱分三项记，互相独立：**① 验证码请求结果**（进入“输入验证码”，还是提示原文）；**② 邮件是否送达**（耗时、是否垃圾箱）；**③ 验证码能否完成登录**。

1. 先确认发信配置：Resend 域名状态为 Verified，Supabase SMTP 已启用；否则收件地址受限，QQ / 163 项标「环境阻塞」。
2. 用同一浏览器配置依次测 Gmail、QQ、163；每次间隔 ≥ 1 分钟，避免撞每小时上限。
3. 记发送时间 T0、收到时间 T1（耗时 = T1 − T0）、邮件头里的发件域名与 DKIM / SPF 结果（Gmail 看“显示原始邮件”）。
4. QQ、163 优先看垃圾箱；没收到不要重复点发送，先等 2 分钟。
5. 每个邮箱登录成功后，做一次 U1L1、退出、重登，确认 XP 一致。
6. 大陆网络下的系统浏览器、微信内置浏览器另测（本轮暂缓）。
7. 截图遮住邮箱和验证码；不要把验证码、key、密码写进任何记录。
