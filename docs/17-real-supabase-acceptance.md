# 真实 Supabase 验收（#11）

和“假服务器/PostgreSQL 模拟测试”分开记录。结果写在本文件末尾的表里（日期、谁做的、通过/失败、证据）。
全程只用项目网址 + 公开 key；**不要**用或发送 secret/service_role 密钥、数据库密码、Supabase 账号密码。

## 0. 前置（需要项目负责人在后台点）
1. SQL Editor 运行 `supabase/schema.sql`（已做过的话跳过）。再运行 `supabase/check-readonly.sql`，把 7 段结果截图贴回，逐段对照注释里的“期望”。
2. Authentication → Email Templates：**Confirm sign up** 和 **Magic Link** 两个模板正文都要包含 `{{ .Token }}`（6 位数字），不要只有链接。保存后各用一个新邮箱触发一次，确认邮件里是 6 位数字。
3. Authentication → SMTP：Resend 已 Verified；发件人用已验证域名；确认不是内置 SMTP（每小时 2 封、只发团队成员）。
4. 准备三个邮箱：**A**、**B**（长期测试账号）、**D**（专门用来测删除，测完就没了）。

## 1. 预览/测试入口

## 2. 验收项（每项记录：通过/失败 + 截图或日志）
| # | 场景 | 步骤 | 期望 |
|---|---|---|---|
| 1 | 真实邮件 | A 邮箱输入 → 发送验证码 | 几十秒内收到 6 位数字，不是链接；提示和重发按钮正常 |
| 2 | 登录并保持 | 输入验证码登录；关闭页面再打开 | 仍是登录状态，进度还在 |
| 3 | 同步 | A 完成 1 关 | 「我的」页显示已同步 |
| 4 | 跨设备恢复 | A 在另一台设备（或另一个浏览器）登录 | 看到同样的 XP、已完成关卡、连续天数 |
| 5 | 账号隔离 | B 在第三台设备登录 | 看不到 A 的任何进度；A 之后再学，B 不变 |
| 6 | 断网重连 | A 设备飞行模式学 1 关，再联网 | 自动补传；云端 XP 只增加一次；另一台设备追上 |
| 7 | 退出再登录 | A 退出 → 再登录 | 进度完整恢复，游客记录（若有）未被误删 |
| 8 | 切换账号 | A 退出 → 用 B 登录 | 只显示 B 的进度 |
| 9 | 直接写表被拒 | 浏览器控制台或 curl，用 A 的登录令牌 + 公开 key 对 `/rest/v1/progress` 发 PATCH/POST/DELETE | 被拒（401/403/权限错误），数据不变 |
| 10 | 跨账号读取被拒 | 用 A 的令牌 GET `/rest/v1/progress?select=*` | 只返回 A 自己的一行 |
| 11 | 并发版本冲突 | 两台设备同时（离线各学，同时联网）同步 | 不丢任何一边的 XP；总数 = 两边之和 |
| 12 | 验证码错误/过期 | 输错验证码；等过期后再用 | 提示“验证码错误或已过期”，有“重新发送”，没有登录、没有产生云端数据 |
| 13 | 自助删除 | 只用 **D**：登录、学 1 关、「我的」→ 删除账号 | 云端该行和账号都没了；用 D 再登录当作新账号、0 XP；A、B 不受影响 |

curl 示例（第 9、10 项，令牌从浏览器 localStorage 的 `suipian.auth` 里取，**只用在你自己的测试账号上**）：
```
curl -s -X PATCH "$URL/rest/v1/progress?user_id=eq.<自己的uid>" -H "apikey: $PUBLISHABLE" -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"rev":999}'
```
