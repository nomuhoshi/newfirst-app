# 备份与恢复（Supabase 继续用免费版，不升 Pro）

更新：2026-11-04。分支 `sonnet/progress-export`。
**状态说明：用户侧的“导出 / 导入进度文件”已实现并有自动测试；数据库侧的备份、恢复步骤是按官方工具写的操作手册，我没有 Supabase 项目的访问权，没有在真实项目上跑过——第一次做时请按第 3 节“演练一次”确认。**

## 1. 一共三层保险

| 层 | 谁负责 | 状态 |
|---|---|---|
| ① 用户自己的进度文件 | 用户（“我的”页 → 备份学习记录 → 导出） | 已做，有测试（`tests/progress-file.test.mjs`） |
| ② 程序改版时旧记录读不懂 → 先留一份原文再重置 | 程序（`storage.js`） | 已做（`sonnet/data-keep-forever`，已并入集成分支）；导出文件会把这些原文一起带走 |
| ③ 数据库定期导出，放在项目主人自己保管的地方 | 项目主人 | 本文第 2、3 节 |

升级套餐（Pro）只多了一份每日自动备份，**解决不了“改版时把旧记录读错”**——那个靠迁移加测试（`docs/19-data-promise.md` 的 5 条规矩 + `tests/data-compat.test.mjs`）。

## 2. 用户侧：导出和导入进度文件

- 入口：“我的”页 → “备份学习记录”。
- 导出：下载 `suipian-progress-YYYY-MM-DD.json`（iPhone：Safari 下载到“文件”App → 下载）。里面是当前进度（关卡、XP、连续天数等），以及程序曾经读不懂而留下的旧记录原文。
- 导入：选这个文件 → 先显示“文件里有几关、多少 XP”→ 点“确认导入”才会改。**只合并，不覆盖**：关卡取并集，XP 取较大的，连续天数跟着“最后学习日期较新”的一边；当前设备的红心和声音设置不动。所以导入一份旧文件不会让现有进度变少。
- 已登录账号时不显示“导入”：这时进度以云端为准，导入会让 XP 在多设备间重复累加。导出仍然可用。
- **所以要把文件导回来，必须在未登录状态下做**；已登录时要导入，请先退出登录，导入完再登录。登录成功只代表身份通过，“我的”页看到“已同步 ✓”之后，才说明进度已经上传到云端。
- 文件只含学习进度，不含邮箱、密码、登录凭证。

## 3. 项目主人：每周导出一次数据库（建议和“防暂停”一起做）

免费版没有自动备份。**每周做一次下面任意一种，文件存到你自己的云盘或电脑，不要发给任何人（里面有用户的学习记录和账号 ID）。**

### 方法 A：后台导出（最简单，iPad 能做）
1. Supabase 后台 → SQL Editor → 运行：`select user_id, rev, updated_at, doc from public.progress order by updated_at desc;`
2. 结果区右上角 “Download CSV”，或在 Table Editor 打开 `progress` 表 → “Export” → CSV。
3. 文件名带日期保存，如 `progress-2026-11-04.csv`。

### 方法 B：命令行完整导出（在你自己的电脑上）
1. 后台 Project Settings → Database → Connection string，复制连接串（含数据库密码；**不要贴给任何人，包括 AI**）。如果电脑只有 IPv4，用页面上提供的 Session pooler 连接串。
2. 运行（二选一）：
   - `supabase db dump --db-url "<连接串>" --data-only -f backup-$(date +%F).sql`
   - `pg_dump "<连接串>" --data-only --table=public.progress --file=backup-$(date +%F).sql`
3. 想连账号一起备份：另外导出 Authentication → Users 列表（后台有导出入口）；`progress.user_id` 指向 `auth.users`，只恢复进度表而没有对应账号会写不进去。

### 恢复
- **同一个项目里表被误改 / 误删**：先在 SQL Editor 运行 `supabase/schema.sql`（幂等，会重建表和权限），再导回数据：
  - 方法 A 的 CSV：Table Editor → `progress` → Import data from CSV；
  - 方法 B 的 `.sql`：`psql "<连接串>" -f backup-日期.sql`。
  - 后台 SQL Editor 是项目所有者身份，不受“表只读”限制，可以直接写入。
- **项目被删 / 暂停后无法恢复，要换新项目**：新建项目 → 按 `docs/supabase-setup.md` 重做登录配置 → 运行 `schema.sql` → 用户需要重新用邮箱登录一次（新项目里是新的账号 ID，旧进度行对不上）。**这种情况靠用户自己的进度文件（第 2 节）：先在“未登录”状态下导入文件（已登录时没有“导入”按钮，要导入请先退出登录），确认关卡和 XP 回来了，再用邮箱登录；新账号里没有进度，会把这台设备上的记录自动带上云，登录后等“我的”页显示“已同步 ✓”才算完成。** 这是第 2 节存在的主要原因。
- **恢复后的检查**：`select count(*) from public.progress;` 和备份前一致；挑 2 个测试账号登录，核对关卡和 XP。

### 演练一次（必须做，不然备份等于没有）
用一个测试项目（或测试账号的行）：导出 → 删掉那一行 → 按“恢复”导回 → 登录核对。第一次做完把实际踩到的坑补进本文。

## 4. 防暂停

免费版连续一周没有访问会暂停项目；暂停期间登录和同步不可用，数据保留，后台可一键恢复。每周的备份动作本身就是一次后台访问。定时访问脚本是否算“活动”**未验证**，不要当作已解决。

## 5. 以后改动的硬规则

动关卡 ID、本机存档格式、云端文档格式或同步逻辑，**必须**：
1. 先读 `docs/19-data-promise.md`；
2. 把旧版真实样本放进 `tests/fixtures/` 并让 `tests/data-compat.test.mjs` 通过（不为了过测试去改样本）；
3. 本机格式升级写迁移，不允许走“无法识别 → 从头开始”；
4. 云端字段变化同时升 `SCHEMA`；先发“能读新格式”的版本，等大家都更新后再发“开始写新格式”的版本。
5. 同步层改动合并前建议用 Opus 复核（TEAM.md）。

## 6. 云存档验收顺序（真人做，见 `docs/18-真人验收清单.md`）
1. 真实邮箱收 6 位验证码 → 登录；
2. 手机 A 做完一关 → 等“我的”页显示“已同步”（登录成功只代表身份通过，看到“已同步”才说明进度已上传）；
3. 手机 B 登录同一账号 → 核对关卡和 XP；
4. 在同一个测试地址（`pr11/`）发布一次更新 → 再核对关卡、XP、连续天数；
5. 顺手导出一份进度文件，换一台**未登录**的设备（或先退出登录）导入看看；
6. 全部通过后再提交上线决定。
