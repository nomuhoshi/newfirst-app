## 0. 怎么读这份大纲

**题型代号**
| 代号 | 题型 | 现状 |
|---|---|---|
| P | predict 选输出 | 已有 |
| F | fill 点词块填空 / 修程序 | 已有 |
| O | order 点代码行排顺序 | 已有 |
| M | modify 改代码：给一段能运行但结果不对（或报错）的程序，改到通过测试 | 待实现（docs/u3-and-code-tasks-plan.md） |
| W | write 写代码：只给题目和测试数据，自己写；单元项目和毕业作品用 | 待实现 |

**每个单元的顺序：示范 → 练习 → 逐步撤掉提示**
- 示范（D）：开场代码 + P/O 题，学生先“看懂”。
- 练习（R）：F/M 题，代码大部分给好，学生补关键处。
- 放手（S）：M/W 题，提示从“知识点 → 思路 → 参考解法”三级逐步撤掉；单元项目（W）只保留第一、二级提示，参考解法要主动展开，展开后按 SPEC §4.2 标“已查看解答”。

**硬性要求（每单元都满足）**
- 至少一道真实的写代码或改代码题（M 或 W）。U1、U2 现在只有 P/F/O，补 M 题见各单元“新增”行。
- 单元项目至少两组测试数据，按输出判分，接受不同的合理写法（不比对参考代码）。
- 毕业作品（U12 最后一关）从空白编辑器开始。

**阻塞标记**
- ⛔input：需要运行时支持 `input()`（现在 SPEC §8.2 明确不支持交互输入）。
- ⛔多文件：需要一关里同时编辑 / 导入多个 .py 文件。
- ⛔文件：需要沙箱内的文件读写（Pyodide 虚拟文件系统，每次运行重置）。
带标记的关卡在运行时支持前**不上线**，路线图显示“即将推出”。可以先用“预先给好的变量”代替的，在备注里写了替代做法。
