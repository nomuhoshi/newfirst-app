## 1. 规格中的矛盾、风险和阻塞

### 阻塞（必须先决定）
1. **私有仓库不能免费用 GitHub Pages。** GitHub Free 个人账号的 Pages 只支持公开仓库；Pro 账号也不能私密发布（官方文档）。三个选项：
   - A. 把 `first-app` 改成公开（最简单；先把 `docs/01-context.md` 里的个人信息删减）。
   - B. 源码保持私有，另建公开仓库 `first-app-site` 只放构建后的网页。
   - C. 用 Cloudflare Pages（免费，支持私有仓库；需要你注册账号并点几下授权）。
   - **建议 A**：步骤最少，对新手最友好；内容本来就是要公开的学习应用。
2. **iPhone 真机验证只能由你来做。** 我这边只有桌面浏览器。需要知道：你和测试同学的**手机型号、iOS 版本**，以及是否有安卓机。

### 内容问题（不阻塞，但要改规格措辞）
3. **N09 平均值必然出现小数。** Python 里 `/` 一定返回小数：`sum([2,4,6]) / len([2,4,6])` 打印 `4.0`。规格说“尽量整数结果”，但这一节做不到。建议：**正面教 `4.0` 为什么有 `.0`**，测试数据选能整除的数，预期输出写 `4.0`；不在首发引入 `round` 或格式化。
4. **N05 一节塞了太多新概念**：比较符号（`>`、`==`）、冒号、缩进、if/else，3–5 分钟很难讲清。建议拆成 N05a（比较与 True/False）和 N05b（if/else 与缩进），总节点变 11 个；或保持 10 个但把比较符号挪到 N03。
5. **错误提示需要“翻译层”。** Python 原始错误是英文，还带内部调用帧。需要做：只保留用户代码的行号和错误类型，再按错误类型（SyntaxError、NameError、IndentationError、TypeError、ZeroDivisionError 等课程范围内的约 8 种）配中文说明。这是额外工作量，计入第 2 步。

### 范围风险（建议，不强制）
6. **规模比最初大了很多。** 从“一个词源题功能”变成“10 节课 + 自制键盘 + 真 Python 运行 + 复习 + 离线”。对新手 + AI 来说可行，但周期会是**几周**，不是几天。规格 §8.4 的顺序（先验证技术，再做一个完整闭环，再填内容）是对的，我完全照这个走。
7. **建议首发砍掉“学习背景”选择。** 规格里它只用来显示一个标签，没有任何功能差异，还多一步引导。“学习目的”两个入口最终都进同一棵树，也可以后做。去掉后首次打开直接进知识树，更符合“碎片时间”。**这条改变范围，需要你确认。**

### 小问题
8. 退缩进按钮没定名字。建议标为 **`⇧Tab`**（Shift+Tab 的常见写法），不新增英文词。
9. Undo“至少二十次”：CodeMirror 默认会把快速连续输入合并。改成**每次按键一步**（自定义键盘每次点击单独记一条历史），实测可以做到。
10. Pyodide 是 MPL-2.0 许可证，随站点托管时要在“帮助”页附许可证说明。

## 2. 技术方案（最简单、适合新手）

| 部分 | 选择 | 为什么 |
|---|---|---|
| 语言 | **普通 JavaScript**（不用 TypeScript） | 少一层要学的东西 |
| 界面 | **不用框架**（不用 React/Vue），直接写 HTML + JS | 页面只有 4 个，框架反而增加学习量 |
| 构建工具 | **Vite 8** | 一条命令启动开发服务器，打包静态网站；支持子路径部署 |
| 代码编辑器 | **CodeMirror 6**（view 6.43 / state 6.7 / commands 6.11 / autocomplete 6.20 / lang-python 6.2） | 括号配对、缩进、撤销都已内置且实测符合规格；可设置 `inputmode="none"` 关闭系统键盘 |
| Python 运行 | **Pyodide 314.0.7**，放在 Web Worker 里 | 浏览器内真 Python；实测可终止、可重建 |
| 停止/超时 | `worker.terminate()` + 重建 | 不需要 SharedArrayBuffer，所以**不需要特殊服务器响应头**，GitHub Pages 能用 |
| 本机存储 | `localStorage`，带数据版本号 | 数据量小，最简单 |
| 离线 | 第 4 步手写一个小型 Service Worker | 比引入插件更容易看懂 |
| 托管 | GitHub Pages（需先解决 §1 第 1 条） | 免费、你已有 GitHub |
| 测试 | Playwright（桌面自动测试）+ iPhone 人工清单 | 两者分开记录，不互相冒充 |

所有版本号在开始实现时固定写进 `package.json`。

### 目录结构（计划）
```
first-app/
  index.html
  src/
    main.js          入口
    editor.js        CodeMirror 设置
    keyboard.js      自制键盘
    runner.js        主线程：管理工作线程、超时、Stop
    py-worker.js     工作线程：加载 Pyodide、执行代码
    storage.js       本机记录（第 2 步起）
  content/           课程、题目、词义 JSON（第 2 步起）
  public/pyodide/    构建时从 node_modules 复制，随站点托管
  tests/             Playwright 测试
  spec/  docs/  skills/  spikes/
```

## 4. 第一步：具体交付

**一个网址**，手机打开后看到：

- 顶部：一道题“让程序输出 5”，初始代码为空。
- 中间：CodeMirror 代码区（系统键盘默认不弹出）。
- 下方：自制键盘
  - 操作栏：`Tab` `⇧Tab` `Enter` `Backspace` `Undo` `←` `→` `ABC/系统键盘切换`
  - 字母层（QWERTY）和数字/符号层，可切换
- 按钮：`Run` `Stop`
- 输出区：加载中 / 运行中 / 输出 / 错误 / 超时 / 达到输出上限 / “程序运行完成，没有输出”
- Python 运行环境在打开页面后**后台加载**，不挡住编辑。

**不包含**：课程内容、保存、知识树、离线、词义卡、判分。

## 5. 第一步：验收方法

### 自动测试（我在桌面 Chromium 跑，结果写进仓库）
1. 括号：`(` 自动补 `)`；跳过右括号；空配对退格；选区包裹（A06）
2. 缩进：Tab/⇧Tab 多行；冒号后回车缩进（A07）
3. 编辑：中间插入、替换选区、左右移动、撤销 20 步（A08）
4. 运行：`print(2 + 3)` → `5`；`x = 1` → 无输出提示（A10）
5. 错误：缺冒号、未定义变量 → 显示类型和行号，代码保留，修好后能再运行（A12）
6. 死循环和输出洪水：5 秒超时 / Stop / 输出上限，之后还能正常运行（A13）
7. 连点 Run、运行中切换：不并发，旧结果不覆盖（A14）

### 你在 iPhone 上手动测（我给你一张勾选清单）
- 系统键盘默认不弹出；内置键盘能输入
- 切到系统键盘再切回，代码和光标不丢；两个键盘不同时占满屏幕（A09）
- 键盘打开时，当前编辑行看得见
- 按键大小能正常点
- 记录：手机型号、iOS 版本、**首次打开到“Python 已就绪”用了几秒**、Wi-Fi 还是流量

### 通过标准
自动测试全部通过 + 你的手机清单没有阻塞问题。若内置键盘在 iPhone 上不可靠，我会报告“复现条件、影响、最小替代方案”，不会擅自取消。
