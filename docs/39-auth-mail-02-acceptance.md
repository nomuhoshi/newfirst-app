## A. 已在“已发布产物 + 浏览器内拦截服务器”下验过的（不需要人工重复）

产物 = `preview-dist-acc2` 的真实构建；服务器应答由浏览器内拦截伪造，请求不会发往任何服务器。

- 页面显示的源码提交、云项目；整个过程只访问本机页面和测试项目地址。
- 发送失败各类（S1a–S6）、超时进入验证码页并锁 60 秒、换邮箱不继承旧邮箱的冷却、验证码失败（V1–V4）。
- 选择弹窗「稍后再说」：不写云端、游客进度逐字节不变；处理中点遮罩和 Esc 关不掉；失败后可重试。
- 退出登录的提示（已同步 / 未同步两种）、冲突提示与导出入口、冲突期间「立即同步」点不动。

这些只证明“代码在模拟的服务器应答下行为正确”，**不证明 Supabase 真实返回的状态码和错误码**。

## C. 真实账号链路（阻塞项：需要测试发信条件）

前提：`suipian-test` 能真正发出验证码邮件（自带发信只发给团队成员，且每小时 2 封；否则需要自定义 SMTP，见 `docs/38-smtp-resend-setup.md`）。**SMTP 与域名尚未决定，所以本节暂时阻塞。**

条件具备后，用**一个测试邮箱**按顺序做（全程只发 1–2 封）：

1. 邮箱（含垃圾邮件）收到验证码邮件，正文只有 6 位验证码、没有链接。
2. 输入验证码登录，选“安全合并游客进度”；“我的”页显示已同步。
3. 游客 50 XP 合并后，账号 XP = 50（不是 100，也不是 0）。
4. **另一台设备**（或另一个浏览器）用同一邮箱登录，读回 XP = 50。
5. 在第一台设备断网后再学一关，联网后同步；另一台读回 = 60，不是重复累加。
6. 重试：同步失败后点「立即同步」，XP 不重复累加。
7. 退出登录：已同步时提示“账号里的 N XP 在云端”；有未上传进度时提示不报数字，只说“已同步的进度在云端；还没上传的进度留在这台设备上”。
