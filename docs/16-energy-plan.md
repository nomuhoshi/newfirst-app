# 体力制（真空管）：规格与实现方案

更新：2026-11-03（JST）。作者：Claude。状态：**规则已由 GPT 批准（23:35）；规格阶段，尚未实现**。实现为**独立 PR**，不混进 #19，排在 #19 和真实账号主线之后。
本文只写规格；红心规则在实现合并之前**保持现状**。付费补体力、广告补体力、会员无限体力**本轮均不引入**。

## 1. 规则（GPT 批准，原样落字）

| 项 | 决定 |
|---|---|
| 上限 | 5 格体力 |
| 恢复 | 每 30 分钟恢复 1 格，满格停止累计 |
| 消耗 | 开始一轮普通学习关消耗 1 格 |
| 关内答错 | 不扣体力；保留错误解释、错题回炉和首次作答准确率 |
| 运行、检查、提示、变化题 | 均不额外消耗体力 |
| 超时、输出超限、环境不可用、取消 | 不算作答、不扣体力、不发奖励 |
| 复习关 | 免费；沿用现有"完成后恢复 1 格"的规则，上限仍为 5 |
| 随机练习 | 免费，保持无 XP、无体力变化 |
| 体力为 0 | 不能开始新一轮普通关；可继续已经开始的关、复习和随机练习 |
| XP、解锁、连续天数 | 保持现有规则；每题每轮奖励只结算一次 |

不变的现有数值：5 格上限、30 分钟/格、复习完成 +1 格，都和今天的红心一致，所以**迁移只是换含义，不换数字**。

## 2. 什么时候扣体力（重复扣费是本方案的重点）

- **不消耗**：点开关卡信息卡、进入关卡介绍页、查看地图。
- **消耗**：点"开始学习"，且**第一道题已经准备好（渲染成功）**之后，才做一次"开始这一轮"的提交。题目加载失败 / 环境出错（例如 Python 加载不上）不消耗。
- **一轮的进入资格（entry token）**：提交时在**同一次写入**里完成两件事：体力 −1，并记下本轮 `activeRun = { id, lessonId, startedAt }`。`id` 是随机编号。本轮的任何再次进入（退出、刷新、关闭 PWA 后回来、另一个标签页）看到同一关已有 `activeRun` 就**直接进入，不再扣**。
- 只保存进入资格，**不保存做到第几题**：再次进入仍从第一题开始（沿用现状）。
- 资格什么时候结束：这一轮**完成**时清除；**放弃的轮**在 6 小时后过期（防止永久免费）。6 小时是待确认的建议值，GPT 可改。过期后再开同一关算新一轮、再扣 1 格。
- 同时只允许一个 `activeRun`。如果开始另一关，旧的那一轮视为放弃（旧资格作废，新一轮扣 1 格）。
- 体力降到 0 **不会把正在做的关卡赶出去**；本轮完成后再开新一轮才受限制。
- **原子性**：`suipian.progress` 是单个键，一次 `setItem` 同时写入体力和 `activeRun`。写入失败（存储满、被禁用）→ 视为**没有扣、也没有资格**，界面提示"没能开始这一关"，不进入题目；绝不出现"扣了但资格没存"。写入后立即读回校验，不一致同样按失败处理。
- **连点只扣一次**：开始按钮点一次后立刻禁用 + 提交函数内幂等（已有 `activeRun` 就直接进入）。
- **跨标签页**：提交前**重新读取**存储，再判断是否已有同一关的 `activeRun`、体力是否够，然后写入；写入后读回确认自己的 `id` 在里面。另一个标签页稍晚提交时读到已有资格，直接进入，不会再扣。（本机 `localStorage` 的单键写入是整体替换，没有"写一半"；两个标签页几乎同时提交时，后写的会基于重新读取的最新内容，因此仍只扣一次。测试里要真的开两个标签页并发点击。）

## 3. 恢复与显示

- 沿用 `regenHearts` 的计时逻辑，改名/改含义为"体力恢复"，计时依据 `heartsAt`，**不依赖设备时钟差**（账号同步里已经只存"距离下一格还差多少毫秒"）。
- 满格停止累计；从 4 格恢复到 5 格后 `heartsAt` 重置为现在。
- 完成复习关：+1 格（上限 5）。完成普通关本身不恢复体力。

**视觉**（原创，见 `docs/design/energy-tube.svg`）：
- 简化真空管轮廓：玻璃罩 + 灯丝 + 底座引脚。亮起 = 暖色灯丝加淡光晕；耗尽 = 灯丝熄灭、描边变淡。**同时显示数字"3/5"**，不能只靠颜色区分。**不持续闪烁。**
- 顶栏显示一个真空管图标 + 数字，不再画 5 个。
- 首次出现时旁边的说明："开始一关消耗 1 格，关内答错不扣。每 30 分钟恢复 1 格，复习也能补充体力。"（以后在"我的"页和体力用完的弹窗里保留同样的话。）
- 体力为 0 的弹窗（原 `openNoHearts`）：显示下一格恢复倒计时、"去复习"（免费、完成 +1 格）和"随机练习"（免费、无奖励）；不出现任何购买 / 广告入口。
- 减少动态效果下，亮起 / 熄灭只切换，不做动画。

## 4. 数据与迁移

- **不强行改底层字段名**：`hearts`、`heartsAt` 继续用，含义改为体力格数和恢复计时起点。新增 `rules: 2`（规则版本）和 `activeRun`（可为 null）。游客记录版本号保持 `version: 3`，只多了两个可缺省字段，旧代码读到会忽略。
- **迁移**（加载时执行一次，**幂等**）：
  1. 若 `rules` 已是 2：什么都不做。
  2. 否则：先按**旧规则**调用 `regenHearts` 算出已自然恢复的红心；`hearts` 取这个数（0–5），`heartsAt` 保持，**未满 30 分钟的恢复进度保留**；写入 `rules: 2`、`activeRun: null`。
  3. XP、已通关、连续天数、学习日期、`lessonsCompleted`、偏好**一个字节都不改**。
  4. 重复执行结果不变（因为第 1 步直接返回）；迁移写入失败则**不进入新规则**，继续按内存里的状态显示，下次加载再试。
- **兼容账号同步层（#11）**：文档里的 `hearts: { n, msToNext }` 形状不变，直接承载体力。文档新增可选字段 `rules`（取较大值合并）。`activeRun` **不同步**（它是这台设备的进入资格）。含义：设备 A 开始一轮（体力 5→4，同步到云端），设备 B 若在同步前也开始同一关，会各扣 1 格——这是已知限制（与红心"后写入者覆盖"同类，最多相差一格），要在已知问题里写明并测试。
- 规则版本不一致的两台设备同步：旧版本（rules 1）读到 rules 2 的文档，只读不改体力字段，提示"请更新到最新版本"（具体文案实现时定）。

## 6. 验收测试（实现 PR 必须全部覆盖）

| 场景 | 期望 |
|---|---|
| 连点"开始学习" | 只扣 1 格，只有一个 `activeRun` |
| 开始后退出、重进同一关 | 不再扣；仍从第一题开始 |
| 开始后刷新页面、关闭 PWA 再打开 | 同上 |
| 两个标签页同时点开始（真并发） | 总共只扣 1 格 |
| 满格（5）与恢复边界：29:59 / 30:00 / 恢复到 5 后停止累计 | 数值正确，`heartsAt` 行为正确 |
| 旧记录迁移：红心 3、恢复进行到 20 分钟 | 迁移后体力 3，保留 20 分钟进度；再迁移一次结果不变 |
| 旧记录迁移不动 XP / 通关 / 连续天数 / 学习日期 | 逐字段相等 |
| 写入失败（`setItem` 抛错 / 读回不一致） | 不扣、不进入、有提示；之后恢复正常可重试 |
| 关内答错 | 体力不变；错误解释、错题回炉、首次准确率仍在；奖励只结算一次 |
| 运行、检查、提示、变化题 | 不额外消耗体力 |
| 超时 / 输出超限 / 环境不可用 / 取消 | 不算作答、不扣体力、不发奖励 |
| 体力为 0 | 不能开新一轮普通关；可继续已开始的一轮、做复习和随机练习 |
| 本轮进行中体力归零 | 不被赶出，完成本轮后再开新一轮受限 |
| 复习关 | 免费；完成 +1 格，上限 5 |
| 放弃的一轮过期（6 小时） | 再开同一关算新一轮，扣 1 格 |
| 同步后一致性 | 账号文档里体力数 / 恢复时间与本机一致；`activeRun` 不被同步；旧版本文档不被新版本破坏 |
| 视觉 / 无障碍 | 数字与图标同时显示；耗尽不只靠颜色；无持续闪烁；减少动态效果下无动画；图标有可读名称 |
