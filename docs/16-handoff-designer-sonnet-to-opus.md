## 3. 已完成的内容

**三种材质样片**（页面第一部分，每种都能点，带声音开关）

| | 玻璃 | 橡胶 | 软木 |
|---|---|---|---|
| 手感 | 透亮、脆 | 弹、哑光 | 颗粒、闷 |

**手机原型**（欢迎 → 题目 → 答对 / 答错）

- 4 个状态，可在页面上切换角色材质，也可跳到指定状态。
- 欢迎页：角色、应用名、示例单元的铜色竖线进度（沿用 v3「编程实验室」方向：墨色、暖白、铜色竖线）、开始按钮。
- 题目页：退出、进度条、体力图标、角色、题干、4 个选项、检查按钮。选项选中 → 检查 → 底部弹出反馈。
- 反馈：答对绿色，答错红色，各有一句解释；答错时不揭晓正确答案，按钮是「再试一次」。
- 角色眼睛有常态（会眨眼）、开心、难过三种。
- 减少动态偏好开启时，所有反应只做 120ms 淡闪。
- 浅色和深色主题都做了，跟随系统。

**占位角色「小方」**：圆角方块 + 两只眼睛 + 一条嘴，纯 CSS，没有任何图片素材。它只是为了让三种材质的区别看得出来，不是候选造型。

2. **真机验证**：iPhone 上的触感、声音、玻璃模糊效果、低端机上 `backdrop-filter` 的帧率，都没看过。我在云端环境里写完只做了脚本语法检查，没截过图，也没在浏览器里点过。**可能有我没发现的布局或渲染问题**，尤其是：
  - 软木的颗粒贴图和边缘位移滤镜（`filter:url(#rough)`）在 Safari 上对 HTML 元素是否正常，没验证。
  - 玻璃的色块和代码行背景（`.halo`）比例是按直觉写的，没看过实际效果。

5. **没有对照真实应用的视觉**：我没有读过 `src/` 里现有的 CSS 和组件，原型的色值（铜色 `#a85a24` 等）来自记忆里「v3 编程实验室」的描述，**不是从仓库里的实际样式读出来的**。接手后先对一下真实的颜色和字体，再决定要不要改。

## 5. 下一步（建议顺序）

1. 先发布并打开原型，用 iPhone 看一遍三种材质，确认哪些手感是对的、哪些要重做。这一步需要项目主人参与（他只用 iPhone 和 iPad）。
2. 定角色：形象、颜色、变身规则。定好后写清验收标准（GPT 要求的）。
3. 材质只留一种或做混合：三种样片是为了比较，不一定三选一，也可以按场景分（例如玻璃做获得成就，软木做按钮）。这是你的判断。
4. 把确定的参数交给程序员 Sonnet 接进组件。参数表已经写好，他可以先接一种材质。交付要有手机稿、关键状态和素材标注；这份原型的 `#welcome`/`#question`/`#correct`/`#wrong` 就是关键状态。
