# 访问诊断页（access-test.html）：微信白屏 / 打不开时怎么用、测了什么

更新：2026-11-05（Sonnet2）。给“朋友在微信里打开是白屏”这类问题用：让对方打开 `…/access-test.html`，点“开始测试”，等它跑完，点“复制结果”发回来。

## 它现在会测什么
1. **网站文件**：首页、manifest、图标、`pyodide/pyodide-lock.json` 能不能下载（带状态码、字节数、毫秒）。
2. **主程序**：从首页里读出主程序文件名并下载（下载失败 = 打开应用会白屏）。
3. **Python 工作线程（新）**：从主程序或它预加载的脚本块里找到 `py-worker-<哈希>.js`，下载它，再**真的像应用一样启动一次**（创建模块工作线程 → 下载并启动 Pyodide，约 12MB）。能区分：工作线程文件下载失败 / 浏览器不能创建模块工作线程（微信、QQ 内置浏览器偶尔）/ Pyodide 文件被拦截或中断 / 90 秒内没启动好。
4. **Supabase（配置了才测）**：连通、匿名登录、写入和读回。
5. **结论（新）**：先用大白话写在最上面，也写进报告：全部通过 / 没有网络（离线）/ 主程序没能下载（会白屏）/ Python 没能启动（做运行代码的题会失败，选择题仍可用）/ 云端连不上。
6. **复制**：优先用剪贴板接口，失败再用 `execCommand`；两者都失败时**如实提示长按文字框手动复制**（原来会假装“已复制 ✓”）。
7. **自己出错也不丢结果（新）**：测试页的脚本中途出意外，也会把已有结果和“测试被中断：…”交出来，不会停在“测试中……”。

## 没测的（需要真机 / 真实网络）
- 微信内置浏览器（X5 / WKWebView）里的真实表现、中国大陆网络下的下载速度和拦截。
- 主程序“下载成功但解析 / 执行失败”（只测了能不能下载）。
- 页面本身打不开（域名被拦截时连这个诊断页也看不到——需要让对方换网络或用别的浏览器先打开）。

## 自动测试与复现
`tests/access-test.test.mjs`（22 项；`MOBILE_BROWSER=chromium|webkit`，已接进 `npm run test:mobile`）：A 基线 + 复制；B 拦截 `assets/main-*.js`；C 拦截 `py-worker-*.js` / `pyodide.asm.wasm` / 不能创建 Worker；D 页面打开后断网；E 剪贴板和 execCommand 都失败；F 删掉 `TextDecoder`。
手动复现任一故障：`npm run build` 后起本地服务器，用浏览器开发者工具的 Network → Block request URL 拦截对应文件，或切 Offline，再点“开始测试”。
改动前的页面在同一套测试里只有 6/22 通过。
